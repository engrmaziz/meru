# Phase 2 — Driving Session Engine (Headless)

**Codename:** Pulse  
**Goal:** Start/end a drive with reliable GPS telemetry stored locally — UI can be ugly.  
**Depends on:** Phase 1  
**Unlocks:** Phase 3–4  

---

## Scope
1. Location permissions + primer flows
2. Foreground service + ongoing notification
3. Adaptive GPS sampling + jump filter
4. Trip session model (UUID, timestamps, vehicle_id nullable)
5. Distance / speed / duration accumulators
6. Room: trips + trip_locations (+ pending_sync)
7. Use cases: StartDrive, EndDrive, ObserveTelemetry
8. Unit tests: jump filter, distance math
9. Context7 for Fused Location / Foreground Service APIs

## Out of scope
Pretty Drive UI, sensors/G-force, server sync, scoring

## Exit criteria
- [x] Lock screen 5+ min still records (FG service + sticky notification; field-verify on device)
- [x] GPS jump does not inflate distance (JumpFilter + unit tests)
- [x] Trip persists in Room after end
- [x] Battery: location updates removed on service destroy / end
- [x] BUILD-LOG entry

## Safety
Driving Mode flag exists even if boards aren’t built yet.
